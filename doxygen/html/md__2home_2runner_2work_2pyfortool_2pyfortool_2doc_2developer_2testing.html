Testing Guide

This guide explains how to run and write tests for PyForTool.

Test Suites

PyForTool has two test suites:

Suite Location Framework Purpose
Unit Tests tests/ pytest Test individual methods and classes, and the pyfortool_parallel command
Regression Tests examples/ Bash scripts End-to-end transformation validation (pyfortool command)

Running Tests

Unit Tests (pytest)

# Install pytest if not already installed
pip install pytest pytest-cov
# Run all unit tests
PYTHONPATH=src pytest tests/ -v
# Run specific test file
PYTHONPATH=src pytest tests/test_pyft.py -v
# Run specific test class
PYTHONPATH=src pytest tests/test_pyft.py::TestPYFTInit -v
# Run specific test
PYTHONPATH=src pytest tests/test_pyft.py::TestPYFTInit::test_simple_init -v
# Run with coverage
PYTHONPATH=src pytest tests/ --cov=pyfortool --cov-report=html
# Generate coverage report
PYTHONPATH=src pytest tests/ --cov=pyfortool --cov-report=term-missing

Regression Tests

# Run all regression tests
cd examples && ./tests.sh
# Run specific test (by filename prefix)
cd examples && ./tests.sh test_name
# Update reference files (after manual verification)
cd examples && ./tests.sh --update

How it works:

  1. Copies all *_before.F90 files to a temp directory
  2. Runs pyfortool with the transformation command (from the !#PYFT transfo: comment)
  3. Compares output with corresponding *_after.F90 files

Writing Tests

Test Fixtures

Shared test data is defined in conftest.py. Each fixture returns FORTRAN code as a string:

@pytest.fixture
def fortran_with_subroutine():
"""Module with a subroutine."""
return """
MODULE MOD_TEST
IMPLICIT NONE
CONTAINS
SUBROUTINE SUB(X, Y, Z)
REAL, INTENT(IN) :: X(:)
REAL, INTENT(OUT) :: Z(:)
INTEGER :: I
DO I = 1, SIZE(X)
Z(I) = X(I) * 2.0
END DO
END SUBROUTINE SUB
END MODULE MOD_TEST
"""

PYFT fixtures wrap the code and return a PYFT instance:

@pytest.fixture
def pft_module(fortran_with_subroutine):
with tempfile.TemporaryDirectory() as tmpdir:
fpath = os.path.join(tmpdir, 'test.F90')
with open(fpath, 'w') as f:
f.write(fortran_with_subroutine)
return PYFT(fpath)

Test Example

class TestCosmeticsCase:
"""Tests for upperCase and lowerCase methods."""
@pytest.fixture
def fortran_lowercase(self):
return """
module mod_test
implicit none
contains
subroutine sub_test(x, y)
real, intent(in) :: x
real, intent(out) :: y
end subroutine sub_test
end module mod_test
"""
@pytest.fixture
def pft_lowercase(self, fortran_lowercase):
with tempfile.TemporaryDirectory() as tmpdir:
fpath = os.path.join(tmpdir, 'test.F90')
with open(fpath, 'w') as f:
f.write(fortran_lowercase)
return PYFT(fpath)
def test_uppercase_converts_keywords(self, pft_lowercase):
"""Test that upperCase() converts FORTRAN keywords."""
pft_lowercase.upperCase()
result = pft_lowercase.fortran
assert 'MODULE' in result
assert 'SUBROUTINE' in result

Best Practices

  1. Use descriptive test names: test_remove_unused_removes_variable
  2. Verify the result, not just execution: Use ‘assert 'UNUSED_VAR’ not in after
  3. **Use fixtures for shared data**: Reduces duplication
  4. **Test actual transformation**: Checkpft.fortran` contains expected changes
  5. Provide a tree when the transformation needs one: see below

Transformations Needing the Tree

Some transformations (e.g. ‘addStack('AROME’, ...),addACCRoutineSeq, removeIJDim) only act on scopes listed instopScopesor called, directly or not, from them. Answering this question requires the execution tree; with the default emptyTree`, these methods fail.

Use the pft_with_tree factory fixture (defined in conftest.py). It writes the code in a temporary directory, builds a Tree over this directory and returns a PYFT instance attached to it:

def test_add_acc_routine_seq(self, pft_with_tree, fortran_with_routines):
pft = pft_with_tree(fortran_with_routines)
pft.addACCRoutineSeq(['module:MOD_ROUTINES/sub:ROUTINE_SEQ'])
result = pft.fortran
assert '!$acc routine (ROUTINE_SEQ) seq' in result # stop scope
assert '!$acc routine (CALLEE) seq' in result # called by stop scope
assert 'NOT_CALLED) seq' not in result # outside call tree

Pass the actual scope path (module:MOD/sub:SUB) in stopScopes; with an empty list, nothing is transformed. Testing both cases, and a routine outside the call tree, checks that the tree is really used.

Testing the pyfortool_parallel Command

tests/test_scripting.py calls pyfortool.scripting.mainParallel(argv) directly, with argv as it would be built from the command line. Each test writes a small source tree (several files, in sub-directories) under tmp_path, changes the working directory to it, runs the command and checks the files modified in place. These tests run with the default multiprocessing start method of the Python used (forkserver on Linux from Python 3.14); see Parallel processing and the multiprocessing start method for why mainParallel requests fork itself.
